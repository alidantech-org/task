# Local dashboard reference port

## Purpose

The local dashboard uses `reference/task-workspace-v4.html` as its visual and interaction fixture. The fixture is an unmodified copy of the supplied v4 prototype. `source/apps/local/src/app/reference.css` retains the prototype stylesheet during the initial port so its selectors and tokens can be applied directly from React components.

## Data and behavior boundary

The dashboard renders the active file-backed workspace returned by the local runtime. The prototype's seeded in-memory records are not used as application data. Task creation, status and date changes, document edits, project switching, and workspace events continue through the existing local runtime and workspace operations. Project switcher rows use a plain folder icon; the adjacent Local label identifies the filesystem-backed project.

## Product identity

The product name is **Taskcode**. The dashboard wordmark uses the existing Bricolage Grotesque heading font, with “code” in the dashboard accent. Its custom mark combines code brackets with a task check inside a fine circular outline, without a square or avatar tile. The symbol is shared by the sidebar, standalone light and dark lockups, and SVG favicon; lockups size the wordmark to match the mark's visual height. The hosted shell uses the Taskcode name and matching symbol. The project switcher uses one horizontal row with a plain folder icon, project name, and dropdown chevron; the popover uses a separate Local label with a computer icon and avoids an initial-based avatar.

Presentation state includes the `tsb` sidebar preference tuple (`mode`, width, last visible mode), theme preference, selected task group, Live change history, and document draft conflict state. Filesystem changes without reliable origin metadata are labeled `External`. An open dirty document surfaces reload, keep-editing, and diff actions when the workspace stream reports an on-disk change.

The sidebar defaults to 240px and stores `[mode, width, lastVisibleMode]` under `tsb`. Legacy visibility, compactness, and width keys are read only when no valid `tsb` tuple exists; a previously hidden sidebar retains its last full or mini mode during migration. Sidebar resizing intentionally uses continuous width tracking between 200px and 380px while dragging; each pointer move updates the shell's width variable and separator value directly, then commits the width to React state and persistence on release to avoid rerendering the dashboard throughout the drag. It does not collapse into mini mode at the demo's drag threshold. Mini mode remains available through the sidebar controls, and the resize separator's position and accessible current-width value follow the live drag.

## UI implementation

The dashboard shell and primary pages use the reference's class names and CSS variables, with component-specific additions in `globals.css`. The reference-matched `.body` owns vertical scrolling and mobile navigation clearance, avoiding a second scroll container. Radix primitives provide the custom selects, date picker, and task creation dialog. Markdown documents retain the existing Milkdown rich editor and offer a custom mode selector for switching to a raw Markdown code editor. The reader continues to use the workspace-aware Markdown renderer. The New task dialog follows the prototype's title and group controls; date and group tokens are parsed from the title, and task creation returns to the Board or opens Calendar at the parsed date. Calendar and board interactions use the existing drag-and-drop library and the runtime's task update operation. Activity and Workspace health remain available as routes outside the primary reference navigation.

The dashboard body uses the reference's 15px scrollbar width while retaining the app's shared scrollbar thumb styling elsewhere. Overlay scrollbars remain overlay at mobile widths. The wrapped primary and tool navigation lists use the reference's 2px vertical gap, so sidebar link positions stay aligned when task groups or document folders are expanded.

The global `Ctrl/Cmd+K` command-palette and `Ctrl/Cmd+B` sidebar shortcuts defer to focused text inputs, textareas, search fields, and contenteditable editors so editor and browser text commands keep working. Escape continues to dismiss the command palette and dialogs.

Section entrance animations follow the reference's per-element 45ms stagger, capped at 14. CSS assigns indexes by page structure so React retains ownership of the rendered nodes during navigation and hydration.

The top-bar Live control reports the local runtime connection and lists the three newest file-backed workspace changes from the existing SSE watcher. Event source labels are displayed only when supplied by reliable event metadata; un-attributed filesystem changes are labeled `External`.

Sidebar task groups and document locations show at most four entries before a “More” action opens the full Groups or Documents page; sidebar labels truncate within their available width. Documents use workspace-relative paths as their canonical routes: each folder route lists only its immediate child folders and files, breadcrumbs follow the original directory hierarchy, and the Documents root lists every top-level folder and all workspace documents. List, table, and grid presentations share folder navigation, and a persistent custom control can group visible files by folder or type. Folder groups link into their corresponding path. Historical document-ID URLs redirect to the matching canonical path; historical `/documents/folder/...` links continue to resolve with real workspace paths taking precedence when a folder is literally named `folder`.

Task details open in the reference's slide-in drawer over the Tasks page. The task board remains visible behind the drawer; task status, priority, due date, archive state, and recent-history visibility use the existing file-backed task mutation operations. Board card completion bars derive from each Markdown task checklist. The Tasks toolbar follows the prototype's Board/List toggle and group chips, with task creation and workspace search remaining in the shared top bar. The Tasks filter row provides a custom Status selector for Planned, In progress, Blocked, and Completed, plus Any status; it filters both Board and List views and is included in saved filters. Board sorting disables dnd-kit's `OptimisticSortingPlugin` because it moves React-owned card nodes with `insertAdjacentElement`; React then tries to remove a node from its former parent after cross-column updates and throws `NotFoundError`. The drag feedback uses a cloned card and React retains ownership of the sortable node throughout status changes. The drop handler derives before/after placement from the pointer's position relative to the target card, so same-column reordering does not depend on dnd-kit moving DOM nodes optimistically.

Overview completion counts and ordering use each task's recorded completion transition and display a fixed Monday-first week, as in the prototype. At desktop widths the Overview grid gives Focus now a wider share than the chart column, keeping status pills clear of task titles; titles and metadata truncate with ellipses on narrow screens. The grid stacks at the reference mobile breakpoint. Selecting a day in the seven-day strip opens Calendar at that date. The Overview intentionally omits the four status metric cards and the Groups progress panel shown in the v4 prototype; this is a deliberate product preference and they must not be restored during visual parity work. Keep the separate “Where things stand” status chart. Groups remain available through primary navigation and on the Groups page, which uses the prototype's clickable progress-card grid and calculates completion from non-archived tasks.

The Calendar section uses the prototype's fixed Monday-first weekday order and renders only the complete week rows needed to cover the selected month. Its Unscheduled tray is shown by default only when there are unscheduled tasks; a toolbar toggle beside Month/Week controls visibility when the tray would otherwise be empty. Clicking a calendar task opens its details in the Tasks sheet, while dragging the task reschedules it. Board cards open the same sheet on click and the full card remains the drag surface, without a hover-only drag icon. A board drop that changes status and order persists both fields in one task update, avoiding an intermediate workspace snapshot while the card is moving. The project selector's add and edit dialogs temporarily hide the popover while preserving its mounted state; outside-pointer handling must not dismiss the owning switcher while a dialog is open. Project row menus render above their owning popover so an option click reaches the menu item instead of switching the project underneath. The add dialog supports folder browsing and keeps actionable errors visible until the user corrects the path or closes it. The Documents list loads previews for every workspace document with bounded concurrency so excerpts and word counts do not stop at an arbitrary page limit. The document reader resolves incoming `[[id]]` links through the runtime search index and lists matching workspace records in its “Linked from” panel.

The task board offers Detailed cards and Compact one-line cards, with an independent Group by group checkbox that clusters cards under collapsible group sections inside each status column. The list view offers List, Table, and Grid layouts with shared sorting controls; table headers also sort their column. The view controls stay at the right of the filter row and wrap when space is constrained. Group headers show task counts and due-date counts; collapsed board groups keep all tasks visible as dense one-line cards, and expanded groups use the selected card detail. Group collapse state is saved separately for each status and group. When grouping is off, raw task presentations show at most the ten most recently completed tasks, based on completion history when available; grouped presentations retain all completed tasks so older group work remains accessible. Active tasks are not subject to this limit.

The Code section browses the selected local project with a nested file tree, glob path filtering, text search, Git change statuses, and a Monaco side-by-side or inline diff against `HEAD`. Filtering by a file path expands its matching ancestor folders so the file remains directly selectable. Its React editor uses `@monaco-editor/react`; Monaco is loaded from installed package code, uses Taskcode's theme tokens, and does not fetch the editor from a CDN. The editor includes full-screen mode, persistent system/light/dark themes, find, wrapping, minimap, font sizing, and an explicit read/write toggle. Saves are limited to existing safe text files, use an expected content hash and atomic replacement, and refuse stale writes; unsaved edits prompt before navigation and offer reload after a conflict. The project tree and file-content search run through the local workspace runtime, respect `.gitignore` and protected-path rules, skip symlinks, and cap tree/search work. Markdown links to project files and folders open the Code section, show file change status, and mark missing paths with an actionable notification. Inline code opens project text search, while fenced code offers the same search action.

When changing these screens, compare rendered app styles against the reference at the handoff's viewport and theme sizes. Keep the HTML fixture unchanged. Do not claim pixel parity based only on matching class names or tokens.
